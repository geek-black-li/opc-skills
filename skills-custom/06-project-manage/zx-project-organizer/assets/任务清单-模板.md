### Codex 使用规则

1. “下一候选任务”仅用于交接；没有当前用户授权时不得自动执行。
2. 使用稳定 TASK-001、TASK-002 ID；删除或重排时不得复用旧 ID。
3. 只引用 F、BR、AC、NFR、PERM、DATA、ADR、VERIFY 等 ID，不复制权威正文。
4. 代码写完、验证通过、人工验收是三类事实，必须分别记录。
5. 依赖使用完整 TASK ID，不写 T1、“上一项”或“上一阶段”。
6. 上游文档或基线变化后重新判断任务和旧证据是否失效。

## 7. 拆分与并行规则

| 原则 | 规则 |
|---|---|
| 结果导向 | 一个任务交付一个可独立验证的最小结果 |
| 可跨层闭环 | 为形成可运行能力，可同时修改 UI、接口、领域和数据层 |
| 高风险单列 | 迁移、公共契约、基础设施和权限边界可单列，并注明消费者 |
| 合理粒度 | 以范围内聚、可独立评审和验证闭环判断，不设固定文件数 |
| 显式依赖 | 使用完整 TASK ID；没有依赖写“无” |
| 保护用户工作 | 明确已有修改、不可改文件和兼容对象 |
| 允许并行 | 满足依赖、文件、环境和集成门禁时，无需等待无关阶段 |

## 8. 上游变化、证据与变更

上游变化检查：

- PRD 的 F、BR、AC、NFR、PERM、DATA 变化：复核范围、完成标准、验证和验收。
- UI 规范变化：复核页面任务、状态覆盖和视觉验收。
- ADR、契约、数据或部署变化：复核依赖、迁移、验证和并行关系。
- 代码、schema、lockfile、环境或用户指令变化：复核授权、基线和旧证据。
